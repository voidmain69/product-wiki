# Новий воркер-сервіс

## Кроки

1. **Спочатку contracts.** Якщо сервіс споживає/публікує нову подію — спершу виконай навичку `/add-event`. Скафолдер відмовить, якщо subject-а немає в `packages/contracts/src/events.ts`.

2. **Згенеруй скелет** (НЕ пиши файли вручну — шаблон гарантує конвенції):
   ```bash
   node scripts/new-service.mjs <name> "<опис українською>" <subject-in> <subject-out>
   ```
   - `<name>` — kebab-case латиницею (стає durable-ім'ям консюмера і `@wiki/<name>`).
   - subject-и можна опустити, якщо сервіс не подієвий (напр. періодичний tick).

3. **Реалізуй обробник** у `services/<name>/src/main.ts`, дотримуючись інваріантів:
   - консюмер **ідемпотентний** (at-least-once; ключ — `snapshotRef`/`revisionId`/`event.id`);
   - запис у Postgres + публікація події = **одна транзакція через outbox** (зразок — `services/resolver/src/main.ts`);
   - `traceId` з вхідної події копіюється у вихідну без змін;
   - прямий `bus.publish` — лише якщо БД не пишеться (зразок — `page.unchanged` у fetcher).

4. **Залежності:** тільки `@wiki/*` пакети (`workspace:*`) + зовнішні. НІКОЛИ не імпортуй інший сервіс — спілкування лише через події.

5. **Перевір:**
   ```bash
   pnpm check:arch && pnpm typecheck
   ```

6. **Онови документацію:** карта потоку подій у `README.md` і, якщо змінився пайплайн, `ARCHITECTURE.md` (розділ 6.5).
